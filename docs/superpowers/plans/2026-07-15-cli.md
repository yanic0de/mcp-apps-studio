# CLI + Studio Manifest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `mcp-apps-studio` CLI: scans a user project for `*.stories.mcp.ts`, builds a widget manifest, serves the built studio SPA on localhost with one-time-token auth, exposes `/api/manifest`. Studio consumes the manifest: widget selector + per-widget scenarios; falls back to the built-in demo widget when no manifest is served (plain `vite dev`).

**Architecture:** Story files are TS modules with a default-exported config (`defineWidgetStory` is an identity helper for types). Discovery walks the project (skipping node_modules/.git/dist), transpiles each story with esbuild `transform`, writes a temp `.mjs` NEXT to the story (so its own imports resolve from the user project), imports it, reads the widget HTML relative to the story. The server is plain `node:http`: token via `?token=` query on first hit → HttpOnly cookie for the rest; 401 otherwise; binds 127.0.0.1 only. Studio store drops the hardcoded scenario table for a `widgets[]` + `activeWidgetId` model; the demo widget becomes a fallback manifest entry built in the component layer (store stays free of `?raw` imports so it remains node-testable).

**Tech Stack:** esbuild (transform only), node:http, no other new deps.

## Global Constraints

- Server binds `127.0.0.1` ONLY; every request requires the token (query once → cookie); token comparison is timing-safe; static serving rejects path traversal. (Architecture doc §9, MCPJam Inspector RCE lesson.)
- CLI package name `mcp-apps-studio` (the future npx name), lives in `packages/cli`.
- Studio store must stay importable in node tests — no `?raw`/DOM imports in `store.ts`.
- `live` scenario behavior unchanged: special-cased by scenario name, present only on the demo widget entry.
- Publish story still deferred: bin runs via `tsx` script in-repo.

### Task 3: cli — studio server with token auth

**Files:**
- Create: `packages/cli/src/server.ts`; modify `src/index.ts`
- Test: `packages/cli/src/server.test.ts`

**Interfaces:**
- `generateToken(): string` (32 hex chars)
- `createStudioServer(opts: { studioDist: string; manifest: WidgetManifestEntry[]; token: string }): http.Server` — caller listens on 127.0.0.1

**Behavior:** no/wrong token → 401; `?token=` valid (timing-safe via sha256+timingSafeEqual) → serve + `Set-Cookie: mcp_studio_token=…; HttpOnly; SameSite=Strict; Path=/`; cookie alone → serve; `/api/manifest` → `{ widgets }` JSON, `cache-control: no-store`; static from `studioDist` with mime map, unknown path → `index.html` (SPA fallback); normalized path escaping dist → 403.

**Test sketch:** temp dist with `index.html` + `assets/app.js`; `server.listen(0, '127.0.0.1')`; fetch: 401 без токена; 200 + set-cookie с `?token=`; 200 по cookie; manifest JSON; `/assets/app.js` правильный mime; SPA fallback; wrong token 401.

**Commit:** `feat(cli): localhost studio server with one-time token auth and manifest API`
